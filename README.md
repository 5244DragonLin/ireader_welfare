# ireader_welfare：掌阅福利中心自动化工具

纯 Python 实现的掌阅 App 福利中心自动化工具，凭手机号与密码登录，自动完成签到、两个抽奖、阅读时长、开宝箱、等级经验任务与看视频领券。不起浏览器、不装模拟器、不需要抓包，也不用真的看广告。

这三个掌阅工具构成一条完整链路：[ireader_welfare](https://github.com/5244DragonLin/ireader_welfare) 负责领券，[ireader-picker](https://github.com/5244DragonLin/ireader-picker) 负责用券选书下单，[ireader_bookshelf_exporter](https://github.com/5244DragonLin/ireader_bookshelf_exporter) 负责把买下的书导出为 EPUB。各工具可单独使用，也可串起来覆盖从领券、购书到导出收藏的全过程。

## 💡为什么需要？

- **操作分散，又没有自动化入口**：签到、领奖、转盘、阅读时长、开宝箱、等级任务散落在福利中心和「我的」页不同位置，掌阅也没有自动化入口；本工具把这些动作收敛成一条命令
- **阅读和看视频太费时间**：阅读赚代金券 10 档合计 180 分钟，手动读费时费力；看视频每次要看完整段广告才给 10 代金券，一天十次就是十分钟。本工具在电脑上几秒铺满时长，直连接口领券，不用看广告
- **代金券有效期只有几天**：签到给的 30 代金券过期作废，本工具自动帮你领，能领的都不落下
- **升级要靠攒经验**：等级任务每天给的经验藏在「我的 → Lv 勋章」里，手动点击领取麻烦，不点就白丢

每天跑一次即可自动完成这些动作，也可以挂到计划任务里。

## ⭐亮点

- **完全后台自动化**：签到、领奖、两个抽奖、阅读时长、看视频领券、分享日签、等级经验任务、品质好书任务全部在电脑上完成，不开 App、不接手机
- **淘书市满减券自动领**：书城滚动栏里的淘书市活动一月约换两次，每期 3~4 张满减券藏在活动页里，工具自动找到当期活动并全部领到，没换期时自动跳过
- **看视频领券远超 App**：App 里每天只能看 10 次广告，本工具能领 30+ 次、拿到 300+ 代金券
- **代金券账目透明**：可列出每一笔的入账时间、面额与来源，不用靠猜
- **重复运行安全**：已领、已报的自动跳过，只补差额
- **到期提醒**：状态面板列出即将过期的代金券，避免浪费
- **密码登录，不走短信**：手机号 + 密码直接登录，一次登录长期有效

## 🚀快速开始

### 1. 克隆项目

```bash
# Gitee 镜像（国内访问快）
git clone https://gitee.com/yhl5244/ireader_welfare.git

# GitHub 原仓库
git clone https://github.com/5244DragonLin/ireader_welfare.git

cd ireader_welfare
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 配置账号

推荐用环境变量，避免密码落盘：

```bash
# Windows
set IREADER_PHONE=你的手机号
set IREADER_PWD=你的密码

# macOS / Linux
export IREADER_PHONE=你的手机号
export IREADER_PWD=你的密码
```

也可以复制配置模板：

```bash
cp config.example.yaml config.yaml
# 编辑 config.yaml 填入 phone / password
```

### 4. 运行

```bash
# 只看状态，不做任何写操作
python src/main.py status

# 执行一条龙（自动先铺阅读时长，再签到领奖抽奖开箱）
python src/main.py run
```

> `run` 已经把「铺阅读时长」并进来了：它会先把 180 分钟阅读时长报到网页版接口，再领 10 档代金券、签到、抽奖、开箱。**日常只需这一条命令**。

### 命令

| 参数 | 说明 |
|------|------|
| `status` | 只查看状态，不做任何写操作 |
| `run` | 铺阅读时长 → 签到 → 领阅读奖 → 领日常任务 → **等级经验任务** → 转盘 → 阅读抽奖 → 开箱 → **看视频领券** → **淘书市满减券**（默认命令） |
| `video` | 只领看视频代金券，逐笔显示面额与剩余次数 |
| `taoshushi` | 只领淘书市活动的满减券（没换期时提示并跳过） |
| `sign` | 只签到并领签到奖励 |
| `wheel` | 把大转盘的次数一次抽完 |
| `lottery` | 领里程碑机会并抽完阅读时长抽奖 |
| `read` | 只领取已达标的阅读奖励 |
| `box` | 只开启已达标的宝箱 |
| `tasks` | 领取已完成的日常任务奖励 |
| `level` | 只做等级成长任务（浏览书城得经验）并领奖 |

> `run` 的顺序已按活动逻辑排好：抽奖排在领奖之后，刚领到的抽奖机会不会被浪费。

## ❓️FAQ

**Q：哪些任务拿不到？为什么不做？**

A：有两项不做，原因不同：

**「打开掌阅APP」（+10 经验值）** —— 判定依据是「App 真的被冷启动过一次」这个事实，而请求本身无法证明进程存在。三条启动上报通道全部试过并已伪造通过签名，仍然拿不到：一条对任何输入都回成功（不校验也不记账），一条只验签名不验内容，一条事件 id 随便填也照收。**纯 HTTP 走不通**，需要时自己打开一次 App 即可。

**「打开携程做任务领 +5 满减券」这类跨 App 换量任务** —— 机制已经完全破解（token 能拿、跳转链接能构造、核销协议已知），但完成判定依赖「对方 App 回跳打开福利页」这个动作：服务端在那一刻把合作方来源写进会话，而**没有任何接口允许客户端自己设置它**。工具里各种传参方式都已试遍，服务端一律以「来源不存在」拒绝。另外，携程那侧的任务页现已显示「活动已结束」，**即使手动跳转也进不去**。**不做自动化**；但工具现在能看见这条任务（`status` 里会列出，并说明需手动完成），若你手动做完，`tasks` 会正常领奖。

其余任务——签到、阅读 10 档、分享日签、两条品质好书任务、等级经验、看视频领券、淘书市满减券——都已纯 HTTP 拿下，`run` 一条命令全部完成。淘书市一月约换两次期，没换期时滚动栏里没有活动入口，工具会安静跳过，属于正常情况不用管。

顺带说下阅读/收听那两条为什么不用真读：它们的判定是两个可重放的部件——① 书单页的「入口曝光」事件；② 官方时长接口 `read/time`。工具会从任务 `jump_url` 抓当日书单（页面每天轮换），补一次曝光再铺时长。收听的时长要用 `res=L`、阅读用 `res=R`，用错类型不报错但永远不计数。

**Q：分享日签怎么做到不开 App 也能领？**

A：反编译还原了 App 的分享上报协议（`/user/scomm/share_report`），`run` / `tasks` 发现任务未完成时会自动补一次上报，服务端直接把任务标记完成并发放 20 代金券。

**Q：阅读时长真的能在电脑上拿满吗？没报满怎么办？**

A：默认就包含在 `run` 里——跑一次 `python src/main.py run`，先铺 180 分钟再领奖，10 档全部拿到，想调整用 `--read-pc-minutes N`。

上报的时段只能铺在「今天零点 → 当前时刻」之间，不占未来时间。所以跑得太早（如凌晨 0:30）最多只能报 30 分钟，靠后的档位自然差分钟数——这不是出错，是任务跑早了。把定时挪到当天较晚的时刻（如凌晨 4:00 之后）即可一次铺满；也可以晚些再跑一次 `run`，已报时段会自动跳过、只补差额。

**Q：凭证会泄露吗？**

A：默认不落盘。开了 `--save` 也只保存账号和昵称等摘要，不包含密码。
